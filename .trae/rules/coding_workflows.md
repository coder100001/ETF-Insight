# Trae 编码工作流 - 类似 gstack 技能

## /plan - 规划工作流

**使用场景**: 开始新功能开发前

**执行步骤**:
1. 阅读 AGENTS.md 和项目文档
2. 分析现有代码结构
3. 创建 TODO 列表
4. 设计数据模型和 API
5. 规划测试策略

**输出**: 详细的实施计划

---

## /review - 代码审查

**使用场景**: 代码完成后

**检查清单**:
- [ ] 代码是否符合项目规范
- [ ] 错误处理是否完善
- [ ] 是否有重复代码
- [ ] 命名是否清晰
- [ ] 是否有潜在 bug
- [ ] 测试是否充分

**输出**: 审查报告和改进建议

---

## /test - 测试驱动

**使用场景**: 编写新功能

**执行步骤**:
1. 先写测试用例
2. 运行测试（应该失败）
3. 实现功能代码
4. 运行测试（应该通过）
5. 重构优化

**输出**: 通过测试的功能代码

---

## /ship - 发布准备

**使用场景**: 准备提交代码

**执行步骤**:
1. 运行所有测试
2. 运行 lint 检查
3. 检查类型错误
4. 格式化代码
5. 生成提交信息
6. 提交并推送

**输出**: 干净的提交

---

## /qa - 质量保证

**使用场景**: 功能完成后验证

**检查清单**:
- [ ] 功能是否符合需求
- [ ] 边界条件是否处理
- [ ] 错误场景是否测试
- [ ] 性能是否可接受
- [ ] 文档是否更新

**输出**: QA 报告

---

## /debug - 调试助手

**使用场景**: 遇到问题

**执行步骤**:
1. 收集错误信息
2. 分析日志
3. 定位问题根源
4. 提出解决方案
5. 验证修复

**输出**: 问题诊断和解决方案

---

## /refactor - 重构建议

**使用场景**: 改进现有代码

**分析维度**:
- 代码重复
- 函数过长
- 圈复杂度过高
- 命名不清晰
- 设计模式应用

**输出**: 重构方案和优化代码

---

## /docs - 文档更新

**使用场景**: 代码变更后更新文档

**检查项**:
- [ ] README 是否需要更新
- [ ] API 文档是否需要更新
- [ ] 代码注释是否需要补充
- [ ] AGENTS.md 是否需要同步

**输出**: 更新后的文档
